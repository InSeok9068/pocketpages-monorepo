# AI 오디오북

| 위치                            | 누가                       | 무엇을                                      |
| ------------------------------- | -------------------------- | ------------------------------------------- |
| 책 상세                         | `users.admin_manager = true` | AI 오디오북 생성 요청·일시 정지·진행률 확인 |
| 리더 → 읽어주기 → AI 오디오북   | 서재에 책이 있는 사용자    | 생성된 음성만 재생. 리더는 생성하지 않음    |
| 리더 → 읽어주기 → 로컬 오디오북 | 모두                       | 기기 음성(Web Speech)으로 재생              |

`admin_manager`는 hidden 필드라 사용자가 API로 직접 바꿀 수 없고, 어드민에서만 설정합니다.
생성된 구간이 하나도 없으면 리더의 AI 오디오북 항목은 비활성화되고 로컬 오디오북이 기본으로 선택됩니다.

## 서버 설정

먼저 `pb_schema.json`의 `book_audio_chunks`, `book_audio_progress`, `book_audio_jobs`, `users.admin_manager`를 관리자에서 import합니다.

서비스 `.env`의 `GEMINI_APIKEY`를 그대로 사용할 수 있습니다.
`GEMINI_API_KEY`, `GEMINI_AI_KEY`도 지원하며 키는 브라우저에 전달하지 않습니다.
책 상세에서 모델을 선택합니다. 기본은 `gemini-3.8-flash-lite-tts`이며 Lite가 사용 중이면 비어 있는 `gemini-3.8-flash-tts`가 선택됩니다.
책 상세와 관리자 도서 목록의 "AI 오디오북 생성" 팝업에서 모델·목소리(`VOICES`, 기본 Sulafat)·스타일(`STYLES`, 기본 차분한 낭독)을 함께 고르며, 첫 요청 때 작업에 저장된 값은 다시 시작해도 바뀌지 않습니다. 스타일은 작업에 문구로 저장되므로 이미 쓰인 문구를 고치면 그 책들은 화면에 이름 대신 문구로 보입니다.
모델 목록·화면 이름·기본 모델은 `book-audio-data.js`의 `MODELS` 한 곳에서 정합니다(에디터용 이름 타입은 `types.d.ts`의 `BookAudioModelName`). 새 모델을 넣기 전에 MP3 출력·`Sulafat` 목소리 지원, 공백 제외 낭독 속도(짧은 음성 기준 초당 6.5자, 재생 바 추정 공백 포함 초당 6.8자), 무료 한도를 한 챕터로 확인합니다.
모델마다 미완료 작업은 한 책만 등록할 수 있습니다. 대기·생성 중·일시 정지·실패 작업이 있으면 해당 책 이름과 함께 선택을 막고, 완료하거나 삭제하면 풀립니다. 예약 시 서버 트랜잭션에서도 다시 확인합니다.
이는 미완료 작업에 따른 제한이며 Gemini의 실제 일일 잔여 요청 수를 조회하는 기능은 아닙니다. 앞선 책이 완료돼도 일일 한도가 소진됐다면 다음 작업은 429 대기 규칙을 따릅니다.

모델·목소리·말투·본문 처리 버전은 최초 작업에 고정하고 설정 해시로 묶습니다. 다시 시작·재생·청취 기록은 저장된 작업의 설정을 사용합니다. 모델을 바꾸려면 오디오북을 삭제한 뒤 다시 요청합니다. `BOOKLOG_TTS_MODEL` 환경변수는 사용하지 않습니다.
생성할 때 본문이 Google에 전달되며, 무료 티어에서는 제품 개선에 사용될 수 있습니다.

## 생성

| 단계        | 동작                                                                                                                                                                                                                                                                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청        | `book_audio_jobs`에 설정만 고정하고 바로 응답합니다. `total_chunks = 0`은 구간 등록 대기 표시입니다.                                                                                                                                                                                                                                                                             |
| 구간 등록   | 다음 cron 실행이 EPUB 전체를 최대 3,000자 구간(문단·문장 경계, 음성 약 7분)으로 나눠 `queued`로 등록합니다. 이 실행은 생성하지 않습니다. 출력 한도 16,384토큰(초당 25토큰, 약 10분 55초) 안에서 하루 요청 수를 줄이기 위한 길이입니다.                                                                                                                                           |
| 생성        | `booklog-audio-book` cron이 2분마다 한 구간을 만듭니다. 책의 처음부터 순서대로 생성합니다.                                                                                                                                                                                                                                                                                       |
| 429         | 해당 구간은 시도 횟수를 늘리지 않고, 작업 전체를 30분 쉽니다.                                                                                                                                                                                                                                                                                                                    |
| 정책 차단   | `400 Request blocked … policy`. 그 구간만 10분 뒤로 미루고, 작업은 쉬지 않고 다음 구간을 생성합니다. 같은 본문을 다시 보내도 거의 통과하지 않아, 첫 차단에서 바로 가운데에 가까운 문단·문장 경계로 조각 2개로 나눕니다(원래 구간은 `split`, 조각은 `split_path` 0·1). 조각도 차단되면 다시 나누고(00·01…), 300자 미만은 더 나누지 않고 10분 뒤 1번만 다시 시도한 뒤 기기 음성으로 읽습니다(3,000자 구간은 약 190자까지 나뉨). 이렇게 끝난 조각은 "다시 시작"해도 재시도하지 않고, `regenerate_requested`로만 다시 만듭니다. 조각은 다음 구간보다 먼저 생성합니다.                                                                                                                                                                                                                 |
| 기타 실패   | 구간별 최대 5회(10분 × 시도 횟수 간격)까지 재시도하고, 작업은 10분 쉽니다. 실패 사유는 구간 `error_message`와 로그에 남습니다.                                                                                                                                                                                                                                                   |
| 짧은 음성   | 250자 이상 구간·조각의 음성이 공백 제외 초당 6.5자를 넘게 짧으면(정상은 5.1~5.8자, 문장을 건너뛴 음성은 6.5~7.2자) 저장하지 않고 실패 1회로 세어 다시 만듭니다. 시도 횟수가 2회 이상이면 그대로 저장하고 `error_message`에 "짧게 생성됨, 확인" 안내를 남깁니다. 관리자가 들어 보고 `regenerate_requested`로 다시 만들 수 있습니다. |
| 일시 정지   | 진행 중인 한 구간은 마저 저장하고, 이후 구간은 만들지 않습니다.                                                                                                                                                                                                                                                                                                                  |
| 다시 시작   | 실패 구간·조각의 시도 횟수를 초기화하고, 현재 본문과 맞지 않는 옛 구간과 그 조각을 정리합니다.                                                                                                                                                                                                                                                                                                  |
| 구간 재생성 | 어드민에서 `book_audio_chunks.regenerate_requested`를 true로 바꾸면, 다음 실행에서 그 구간의 음성 파일·시도 횟수·재시도 시각·오류를 지우고 `queued`로 되돌립니다. 나뉜 구간이면 조각도 지우고 원래 구간부터 다시 만듭니다. 정책 차단이 반복돼 멈춘 구간·조각은 같은 본문을 다시 보내지 않고 80자까지 둘로 나눠 다시 만들며, 80자 미만이면 그대로 다시 보냅니다. 끝난 작업은 다시 진행 상태가 됩니다. 같은 모델에 다른 책의 미완료 작업이 있으면 해제될 때까지 기다립니다. 생성 중인 구간은 끝난 뒤 처리합니다. 완성된 구간이 이상하게 들릴 때(누락, 음색) 다시 만들 때 씁니다. |

- 책 상세의 **오디오북 삭제**는 그 EPUB의 모든 낭독 설정 음성 파일·구간·작업·청취 기록을 지웁니다. EPUB 원본은 남습니다. 생성 중이던 구간은 결과를 저장하지 않고 버립니다.
- 생성 소유권은 DB 트랜잭션으로 확보하므로 cron 실행이 겹쳐도 같은 구간을 두 번 만들지 않습니다. Gemini 요청 제한 시간은 300초, 생성 소유권 유효 시간은 10분입니다. 소유권 유효 시간이 생성 시간보다 짧으면 진행 중인 구간을 중단으로 보고 다시 요청해 한도를 두 번 쓰므로, 항상 제한 시간보다 길게 둡니다.
- 음성은 Gemini가 직접 출력한 MP3(128kbps, 1시간 약 58MB)로 저장합니다. 권장 모델은 `gemini-3.8-flash-lite-tts`이며, Opus와 `bit_rate` 지정은 지원하지 않습니다(400). `gemini-3.8-flash-tts`의 MP3 지원은 확인하지 않았습니다.
- 관리자 도서 목록의 "오디오 압축"에서 96·64·48kbps를 고르면 `book_audio_jobs.compress_kbps`에 저장하고, `booklog-audio-compress` cron(5분마다)이 완성된 구간을 5개씩 `lame`(Docker 이미지에 포함)으로 모노 재압축합니다. 압축한 구간은 `book_audio_chunks.audio_kbps`에 값을 남기며 0은 128kbps 원본입니다. 원본은 남지 않아 되돌리려면 재생성해야 하고, 재생성한 구간은 다시 원본(0)이 되어 다음 실행에서 같은 값으로 압축됩니다. 낭독은 64kbps 모노가 보편적이며 128kbps 대비 용량이 절반입니다.
- 관리자 도서 목록의 "보관 파일 받기"(`GET /xapi/books/audio-archive`)는 그 책의 구간 레코드와 청취 위치를 `manifest.json`(`format: booklog-audio-archive`, `version: 1`)으로, 완성된 구간의 MP3 원본을 `audio/<구간 ID>.mp3`로 묶은 tar를 내려줍니다. 서버 임시 폴더(`booklog-audio-archive-*`)에서 묶어 바로 지우고, 남은 폴더는 6시간 뒤 다음 보관·복원 때 정리합니다. 생성 중이거나 재시도할 수 있던 구간은 대기로, 반복 차단 조각과 나눈 부모 구간은 시도 기록과 함께 보관합니다.
- 오디오북이 없는 EPUB에는 "보관 파일로 복원"(`POST`, 이 경로만 업로드 2GB, 나머지는 128MB)이 보입니다. 업로드는 메모리에 올리지 않고 임시 폴더로 흘려 쓰고, 압축을 풀기 전에 `manifest.json`·`audio/*.mp3` 외 항목, 경로 탈출, 링크, 중복 이름을 거절합니다. 목록의 본문 해시와 음성 파일이 맞지 않아도 거절합니다. 복원은 한 트랜잭션에서 작업·구간을 만든 뒤 현재 EPUB으로 `planJob`을 돌려, 구간 등록과 같은 기준(챕터·구간 순서, 본문 해시)으로 맞는 구간만 음성을 쓰고 달라진 구간은 생성 대기로 둡니다. 모두 맞으면 생성 완료, 다시 만들 구간이 있으면 일시 정지로 복원해 관리자가 다시 시작하기 전에는 한도를 쓰지 않습니다. 청취 위치는 가리키던 구간의 본문이 같고 사용자가 남아 있을 때만 되살립니다. 이미 오디오북이 있는 EPUB에는 복원하지 않습니다.
- 무료 티어 한도는 모델별로 따로 잡힙니다. 2026-10-15 기준 `gemini-3.8-flash-tts`는 하루 10회였습니다.
- 진행률은 cron이 구간을 저장할 때마다 갱신되며, 책 상세를 새로고침하면 반영됩니다.

## 재생과 청취 기록

- 리더는 `/api/books/audio-chunk`로 구간을 조회합니다. 아직 생성 전이거나 재시도 중인 구간·조각도 원문(`fallbackText`, `pending: true`)을 함께 받아 기기 음성으로 읽고 넘어가므로, 생성 중인 책도 끊기지 않고 이어 듣습니다. 생성이 끝나면 다음에 들을 때 AI 음성으로 바뀌고, 미리 받아 둔 다음 구간에 생성 전 조각이 있었으면 넘어갈 때 한 번 더 조회합니다.
- 본문 파일(XHTML)이 16MB를 넘으면 챕터가 빠진 채 완료되지 않도록 구간 등록을 실패로 멈추고 작업 `error_message`에 이유를 남깁니다.
- 나뉜 구간은 모든 조각이 준비된 뒤 `parts`로 한 번에 받아 순서대로 이어 재생합니다. 청취 위치는 조각 길이를 이어 붙인 구간 내 시간으로 저장합니다.
- 재시도를 모두 소진한 구간·조각(정책 차단 등)은 원문(`fallbackText`)을 받아 기기 음성(Web Speech, ko-KR)으로 문장 단위로 읽고 다음 AI 음성 구간으로 이어갑니다. 한도를 쓰지 않으며, 청취 위치와 챕터 완료도 저장합니다. 나중에 "생성 다시 시작"으로 AI 음성이 만들어지면 그 음성으로 바뀝니다.
- 다음 구간을 미리 받고, 미리 받지 못했으면 넘어갈 때 한 번 더 조회합니다. 그사이 생성이 끝났으면 이어서 재생합니다.
- MP3 MediaSource를 지원하는 브라우저는 하나의 `SourceBuffer`에 음성을 순서대로 붙여 조각·챕터 경계에서 `audio.src`를 교체하지 않습니다. 현재 재생 위치에서 앞쪽 약 120초를 준비하고, 지나간 30초 이전 음성은 주기적으로 제거합니다. 파일 단위로 받으므로 한 파일이 길면 준비 범위를 넘을 수 있으며, 책 전체나 서버 합본을 만들지는 않습니다.
- 탐색·챕터 직접 이동은 해당 위치에서 버퍼를 다시 준비합니다. 미생성·실패 조각은 기존 기기 음성으로 읽은 뒤 AI 버퍼를 새로 시작하며, MediaSource 미지원이나 버퍼 오류 시에는 기존 파일별 재생을 사용합니다. 관리자 진단의 `playbackMode`, `buffer-start`·`buffer-append`·`buffer-boundary`·`buffer-trim`·`buffer-fallback`으로 경로와 전환을 확인합니다.
- 관리자 읽어주기 팝업의 벌레 아이콘에서 진단 기록을 시작·중지·복사·삭제합니다. 기록은 기본 꺼짐이며 페이지를 새로 열면 다시 꺼집니다. 이전 기록이 남아 있으면 새로 열린 페이지는 `page-init`(백그라운드에서 버려졌는지 `wasDiscarded` 포함) 한 줄만 남겨 재시작 지점을 표시합니다. 켜 둔 동안에만 기기에 최근 1,000개 이벤트를 저장하고, 오류는 이름과 안내 문구를 함께 남깁니다. 리더 진입·기록 시작 시 같은 사용자의 7일 지난 기록과 최근 3권을 넘는 기록을 정리합니다. 서버에는 전송하지 않으며 다른 기기의 기록과 청취 위치에는 영향을 주지 않습니다.
- 파일은 보호 파일입니다. 다운로드 경로에서 매번 원본 EPUB의 서재 접근 권한을 확인합니다.
- 브라우저에는 최근 16개 구간을 다운로드 캐시로 보관합니다.
- 사용자·EPUB·낭독 설정·챕터별로 구간, 구간 내 시간, 완료 상태를 DB에 저장하므로 다른 기기에서도 이어 듣습니다.
- 재생 중 15초 간격으로, 재생 시작·일시 정지·정지·페이지 종료 시에도 저장합니다. 저장 실패 시 브라우저에 임시 보관 후 다음 이어 듣기 전에 다시 전송합니다.
- **지금 보는 곳부터 듣기**는 리더 화면 안의 첫 문장(공백 제외 40자 이상)을 구간에서 찾아, 그 문장의 글자 비율 위치(AI 음성은 약 1초 앞, 기기 음성은 그 문장)부터 재생합니다. 찾지 못하면 챕터 처음부터 재생하고 안내합니다.
- 챕터를 다 들으면 구간이 있는 다음 챕터로 자동으로 넘어갑니다(목차·표지처럼 본문 없는 항목은 건너뜀). 마지막 챕터에서 멈춥니다.
- 완료한 챕터에서 재생을 누르면(이어 듣기) 다음 챕터 처음부터 재생합니다.
- 재생 전에는 이어 듣기 버튼과 이어질 위치(챕터·챕터 내 시간), 그 아래 보조 버튼 "지금 보는 곳부터 듣기"를 보여주고, 현재 챕터 처음부터는 "다른 위치에서 시작"에 접어 둡니다. 재생을 시작하면 재생 바와 조작 버튼으로 바뀌며, 상태 문구는 오류·기기 음성 대체·동기화 대기 때만 표시합니다.
- 브라우저 기본 플레이어 대신 챕터 단위 재생 바를 씁니다. 챕터의 구간·조각 길이를 이어 붙여 `12:30 / 45:10`처럼 표시하고, 바를 끌거나 15초 앞뒤 이동을 하면 해당 구간·조각의 시간으로 이동합니다. 아직 음성이 없는 구간과 기기 음성 조각은 글자 수(초당 약 6.8자)로 길이를 추정하며, 챕터 처음·끝을 넘어 이동하지 않습니다.
- 재생 중에 읽어주기 패널을 닫으면 화면 아래(뒤로가기·메뉴 버튼 왼쪽)에 미니 플레이어가 나타납니다. 재생/일시 정지 버튼과 챕터명·재생 시간을 보여주고, 챕터명을 누르면 패널을 다시 엽니다. 정지하면 사라집니다.
- **듣는 곳으로 이동**은 재생을 멈추지 않고 패널을 닫은 뒤, 리더를 지금 읽는 문장으로 옮깁니다. 조각 안의 재생 시간 비율로 원문 위치를 추정해 그 문장 처음을 챕터에서 찾고(앞 24·14·8자 순), 찾지 못하면 챕터 처음을 엽니다.
- 표지·이미지·판권처럼 낭독 구간이 없는 페이지에서 "현재 챕터 처음부터"·"지금 보는 곳부터 듣기"를 누르면 뒤쪽 첫 본문 챕터부터 재생합니다. 아직 생성 전인 챕터면 "지금 3 / 16번째 챕터를 만들고 있습니다"처럼 생성 위치를, 나눈 조각을 만드는 중이면 그 사실을 안내합니다.
- 챕터 이름 옆의 `7 / 16`은 낭독 구간이 있는 챕터 중 순서입니다. 목차에 없는 파일은 가장 가까운 앞쪽 목차 이름을 빌려 쓰므로, 같은 이름이 이어져도 이 순서로 구분합니다.
- 이전·다음 챕터 버튼은 음성 구간이 있는 이전·다음 챕터의 처음부터 재생합니다(목차·표지처럼 본문 없는 항목은 건너뜀). 떠나는 챕터의 위치는 저장합니다.
- 잠금 화면·알림의 재생/일시 정지/15초 앞뒤 이동/탐색/이전·다음 트랙은 Media Session으로 같은 챕터 재생 바를 조작하며, 챕터 이름과 책 제목을 표시합니다.
- 다른 탭의 늦은 일반 저장은 완료 기록을 취소하지 않습니다. 명시적으로 처음부터 재생하면 완료 상태를 해제합니다.
- 독서 위치·독서 시간과 청취 기록은 별도로 관리합니다.

## 현재 범위

본문 강조 동기화, M4B 내보내기는 포함하지 않습니다.
화면 잠금·백그라운드 연속 재생은 실제 iOS/Android 기기에서 추가 검증이 필요합니다.

## 재생 회귀 테스트

`node --test apps/booklog/__tests__/audio-buffer.test.mjs apps/booklog/__tests__/audio.test.mjs apps/booklog/__tests__/audio-jobs.test.mjs apps/booklog/__tests__/route-health.test.mjs`로 재생·서버 작업·접근 권한을 함께 확인합니다. 브라우저 테스트는 설치된 Chrome을 사용합니다.

| 범위 | 검증 |
| --- | --- |
| 실제 Chrome MSE | 유효한 무음 MP3를 실제 디코더·SourceBuffer로 재생하며 조각·챕터 경계에서 주소 교체와 중간 종료가 없는지 확인 |
| 버퍼와 자원 | 2시간 분량의 위치를 가속 진행하며 앞쪽 다운로드·지난 버퍼·캐시 제한을 확인하고, 시작·정지 반복 후 Object URL이 남지 않는지 확인 |
| 조작과 경합 | 일시 정지 상태 탐색, 제거된 버퍼로 되감기, Media Session 조작, 챕터 이동 중 이전 응답 도착, 다운로드 중 정지 |
| 장애와 복구 | 버퍼 소진 뒤 지연 응답, 네트워크·서버 503 재시도와 횟수 제한, 권한 거절·설정 변경·잘못된 응답, 자동 재생 거절, 재생 도중 버퍼 오류의 파일 재생 전환 |
| 기기 음성 | AI→기기 음성→AI 전환, 중지 후 늦게 도착한 발화 종료 무시 |
| 청취 저장 | 저장 실패 시 기기 임시 보관과 재접속 전송, 구간 내 시간 변환, 실제 PocketBase 파일 스트림·청취 DB를 통한 새로고침 복원과 챕터 완료 |

가속 테스트는 위치를 옮기며 버퍼 관리 주기를 반복하는 테스트이며, 실제 2시간 대기나 휴대폰 절전 정책을 재현하지 않습니다. 브라우저 테스트의 음성은 무음 프레임이므로 스피커·블루투스의 실제 소리 출력과 Android 잠금 화면은 실기기 청취로 확인합니다. `lame`이 없는 환경에서는 실제 재압축 테스트 한 개가 건너뛰어집니다.
